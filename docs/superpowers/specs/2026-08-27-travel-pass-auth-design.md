# 旅行登机牌登录与认证恢复设计

## 目标

将当前未设计的飞书登录、管理员初始化和等待批准页面统一为“旅行登机牌”视觉，并修复已授权管理员在输入初始化口令后又回到登录页、反复授权的问题。

完成标准：

- 首位管理员完成一次飞书授权和一次口令初始化后直接进入行程。
- 管理员刷新页面或重新打开网站时，只要服务端会话仍有效，就自动恢复登录，不再次跳转飞书。
- CloudBase 客户端身份尚未恢复时，不得覆盖已经有效的服务端身份。
- 登录、初始化、等待批准、认证处理中使用同一视觉系统，并支持 320px 以上手机与桌面布局。
- 错误状态留在当前步骤，显示可理解的操作提示，不静默返回登录页。

## 已确认根因

生产数据库显示初始化口令已消费，当前成员已是管理员，且已有多个服务端会话。认证后仍出现登录页不是后端授权失败，而是前端恢复顺序错误：`ProductionAuthGate` 先读取 CloudBase 客户端用户；当 SDK 在自定义票据登录后短暂返回空值时，页面立即切换为未登录，未继续验证仍然有效的 auth-service 会话。

管理员初始化页还会触发认证刷新后立刻导航，两项异步行为没有形成一个可等待的完成条件，进一步放大了这个竞态。

## 视觉方向

采用“A · 旅行登机牌”。

- 主色为纸张米白和深森林绿，橘红用于路线、印章和关键状态。
- 桌面为双栏：左侧是“一鸣 × 美垚”的旅行标题、深港澳珠路线和日期；右侧是登机牌式认证卡。
- 手机改为单栏，先显示精简旅程标题，再显示认证卡；主要按钮保持至少 44px 高。
- 标题使用具有编辑感的中文衬线字体，正文使用清晰的中文无衬线字体；不再使用当前巨大的默认标题和浏览器原生按钮。
- 登机牌卡片通过虚线、票根缺口、路线代码和旅行日期建立记忆点，不依赖外部图片加载。

## 页面与组件

### AuthShell

共享认证页面骨架，负责背景、旅程路线、品牌文字、登机牌卡片和响应式布局。它不处理认证请求。

### LoginPage

显示“使用飞书继续”主按钮。页面加载期间若正在恢复已有会话，按钮不闪现；仅在服务端会话和客户端身份都确认无效后显示登录入口。

### AuthCallbackPage

显示明确的认证进度。根据回调状态进入管理员初始化、等待批准或已批准恢复流程。失败时显示“重新尝试”而不是自动退回登录页。

### BootstrapPage

在同一登机牌卡片内展示一次性口令输入。提交期间禁用按钮。成功后先完成自定义票据登录，再等待统一认证恢复成功，最后进入行程；不再并行刷新和导航。

### PendingApprovalPage

沿用登机牌票根样式展示等待状态和手动刷新。批准后通过同一认证恢复函数进入行程。

## 认证状态流

前端只使用一个恢复入口，按以下顺序判断：

1. 调用 auth-service `/profile` 检查 HttpOnly 服务端会话。
2. 服务端返回管理员或成员时，将该成员视为权威身份。
3. 若 CloudBase 客户端尚无用户，则请求一次自定义票据并完成 CloudBase 登录。
4. 两端身份准备完成后进入行程。
5. `/profile` 返回待批准时进入等待页。
6. `/profile` 明确返回未认证时，才显示飞书登录页。

CloudBase `getCurrentUser()` 只用于判断是否需要补做客户端登录，不再作为否定服务端身份的前置门槛。

管理员初始化成功后的动作按顺序执行：提交口令 → 获取自定义票据 → CloudBase 登录 → 重新读取服务端成员 → 设置 authenticated → 导航首页。任何一步失败都保留在初始化页并提供重试。

## 错误处理

- 服务端会话无效：显示登录页。
- 成员待批准：显示等待批准页。
- 自定义票据登录失败：显示“登录同步未完成，请重试”，不再次发起飞书授权。
- 初始化口令错误：清空输入并显示“口令不正确”。
- 网络错误：保留当前页面和当前认证阶段，允许重试。
- 已完成初始化的管理员再次进入旧回调地址：恢复现有成员身份并进入行程，不再要求口令。

## 测试与验收

- 单元测试复现：服务端 `/profile` 返回管理员、CloudBase `getCurrentUser()` 暂时为空时，最终仍进入行程。
- 单元测试复现：初始化成功后等待恢复完成才导航，且只调用一次自定义票据登录。
- 单元测试覆盖：已有管理员进入带 `status=bootstrap` 的旧回调时不会再次显示口令。
- 组件测试覆盖登录、处理中、初始化、等待批准和错误提示。
- 视觉检查桌面与 320px 手机宽度，确认无溢出、按钮可触达、焦点可见。
- 生产发布后使用真实飞书账号验证一次完整流程，并刷新页面确认不会重新授权。

## 范围

本次只修改认证页面视觉与认证恢复流程，不改成员权限模型、CloudBase 安全策略、行程数据结构或飞书应用权限。
