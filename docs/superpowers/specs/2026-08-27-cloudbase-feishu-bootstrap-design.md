# CloudBase 协作与飞书首次管理员初始化设计

- 状态：待用户审阅
- 日期：2026-08-27
- 范围：现有旅行规划 App 的 CloudBase 实时协作、飞书登录和成员管理

## 目标

一鸣和美垚通过飞书登录同一份旅行计划。首次由一鸣使用一次性初始化码取得管理员身份；美垚首次登录后进入待批准状态。未批准账号不能读取旅行数据，浏览器永远不能取得飞书或腾讯云服务端密钥。

## 配置与密钥边界

根目录 `.env.local` 新增且仅服务端使用：

```dotenv
ADMIN_BOOTSTRAP_CODE=
FEISHU_APP_ID=
FEISHU_APP_SECRET=
FEISHU_REDIRECT_URI=
AUTH_SESSION_SECRET=
TENCENTCLOUD_SECRET_ID=
TENCENTCLOUD_SECRET_KEY=
```

`VITE_CLOUDBASE_ENV_ID` 是唯一允许进入浏览器的 CloudBase 配置。`ADMIN_BOOTSTRAP_CODE` 以哈希形式保存在 CloudBase；成功初始化后立即失效。所有真正的密钥保存到 CloudBase 云函数环境变量，部署后的客户端不读取 `.env.local`。

## 登录与初始化流程

1. 访问者进入应用，未登录时跳转到飞书 OAuth。
2. OAuth 回调云函数校验 state，并以飞书接口换取 `open_id`、显示名和头像；敏感 token 不写日志、不发给浏览器。
3. 若系统尚无管理员，回调页要求输入一次性初始化码；仅验证码正确的账号可写入第一个 `members` 记录，并赋予 `admin` 角色。
4. 系统已有管理员时：已批准成员获得 CloudBase custom-login ticket；未知账号只获得最小化“等待管理员批准”页面，不获得旅行数据 ticket。
5. 管理员批准后，成员下次刷新或点击重试即可得到 ticket 并进入行程；拒绝或移除后现有会话在下一次受保护操作/实时订阅时失效。

管理员初始化码错误、超时 state、重复 OAuth code、非允许流程访问均显示通用中文错误，不泄漏账号、成员列表或初始化状态。

## 成员与授权模型

CloudBase 维护独立 `travel_members` 集合，字段为：CloudBase UID、飞书 `open_id`（仅云函数可见）、显示名、头像、`role`（`admin` / `member` / `pending` / `removed`）、创建时间、批准时间和版本号。

- 管理员：批准、拒绝、移除成员；查看待批准队列；保留自己的管理员身份。
- 成员：读取并编辑被授权旅行；不可查看或管理成员列表中的私密身份字段。
- 待批准/移除/匿名：不能获取旅行快照、实时订阅、存储上传路径或写命令。

每次角色变更由 `trip-api` 事务执行并写入审计日志。系统禁止删除最后一个管理员；本首版不提供“转让管理员”以避免不必要的权限复杂度。

## 数据与实时协作

旅行文档保存 `memberUids`，数据库规则仅允许 custom-login 且 UID 在该集合内的读取；所有正式写入仍由云函数验证成员资格、版本号和幂等键后进行。前端仅在 approved/admin 状态才建立一个旅行订阅。成员审批、移除或角色变更会推送到当前会话，并将无权限用户带回等待页。

## 界面

- 登录页：`使用飞书登录`。
- 首次初始化页：说明“仅一鸣使用”，提供初始化码输入；成功后跳转总览。
- 待批准页：显示“已登录，等待一鸣批准”，带刷新状态按钮与退出登录。
- 管理员成员页：待批准列表（批准 / 拒绝）、已加入成员（移除），以及每次变更的时间和操作者。此页面不显示原始 open_id。

## 验证

单元测试覆盖：初始化码单次消费、错误码不泄漏、OAuth state 校验、待批准用户不能获得 ticket、管理员审批/移除的事务和最后管理员保护。

端到端测试覆盖：管理员初始化、第二账号待批准、批准后实时进入行程、移除后无法继续读取，以及两个批准账号的行程编辑实时同步。

生产验证覆盖：飞书回调 URL 精确匹配、CloudBase 规则为默认拒绝、云函数环境变量存在性检查只输出通过/失败，永不输出值、长度或哈希。

## 非目标

不实现公众注册、任意人数协作、管理员转让、在浏览器存放服务端密钥，或自动把未批准账号加入旅行。
