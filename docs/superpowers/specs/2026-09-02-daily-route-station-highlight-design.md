# 每日路线站点高亮设计

## 目标

让首页旅行路线图随当前选中的每日计划同步变化，使用户不依赖阅读票面文字，也能快速看出当天所在或途经的城市。此次改动仅涉及前端展示，不改变行程数据模型、后端接口或路线节点顺序。

## 已确认的交互与视觉

- 当前日对应的路线节点使用珊瑚红实心圆、柔和静态光环和珊瑚红站点文字。
- 非当前节点保持现有深绿色；北京起点和终点在非高亮时继续使用现有珊瑚红空心圆。
- 高亮不使用持续呼吸、闪烁或自动动画，避免干扰每日计划阅读。
- 深绿色虚线路径保持原样，不随选中日改变，避免路线和站点同时争夺视觉焦点。
- 日期切换后，路线高亮与票面中的当前航段在同一次 React 渲染中同步更新。

## 城市映射规则

复用当前 `TravelPassHero` 已有的城市拆分语义：将每日计划的 `city` 按 `/` 分隔、去除首尾空白后逐一匹配站点。

| 每日计划地点 | 高亮站点 |
| --- | --- |
| `深圳` | `SZX 深圳` |
| `香港` | `HKG 香港` |
| `澳门` | `MFM 澳门` |
| `珠海` | `ZUH 珠海` |
| `澳门 / 珠海` | `MFM 澳门`、`ZUH 珠海` |
| `珠海 / 北京` | `ZUH 珠海`、右侧返程 `PEK 北京` |

北京在图中有出发和返程两个独立节点。当前既有 D1—D6 数据中，北京只出现在返京日，因此只高亮右侧返程北京，不误亮左侧起点。

无法匹配到既有站点的地点不产生路线高亮，也不阻断页面渲染。未提供有效 `selectedDayId` 时，沿用票面当前的首个有效日回退规则，确保票面与路线图不会显示不同日期的状态。

## 实现方案

采用最小改动方案：在现有静态 SVG 站点 `<g>` 上，根据选中日计算结果增加活动状态属性和样式类。

- 不将六个固定站点重构为新的配置渲染系统；这会扩大改动面，但不会改善当前需求。
- 不拆分现有单条贝塞尔路线，也不增加路径分段高亮。
- 高亮状态只来源于 `trip.days` 和 `selectedDayId`，不新增本地状态，避免票面与路线高亮发生漂移。
- CSS 使用现有深绿、米白和珊瑚红设计变量；光环保持低透明度和静态效果。

## 可访问性

- 路线图继续作为一个整体的 `img` 语义呈现，不把纯展示节点伪装成可点击控件。
- SVG 的无障碍名称随当前日更新，包含日期编号与高亮地点，例如“当前 D5，澳门、珠海已高亮”。
- 高亮同时改变节点填充、光环和文字，不只依赖单一的细微色差。

## 测试与验收

1. 选中深圳、香港、澳门或珠海的单城市日时，只高亮对应的单个站点。
2. 选中 `澳门 / 珠海` 时，澳门和珠海两个站点同时高亮。
3. 选中 `珠海 / 北京` 时，珠海和右侧返程北京同时高亮，左侧出发北京保持非活动状态。
4. 切换选中日后，票面航段、SVG 无障碍名称和活动站点同步更新。
5. `selectedDayId` 无效或缺失时，高亮与票面共同回退到首个有效日。
6. 未知城市不产生错误高亮，路线图仍可正常显示。
7. 桌面和窄屏下光环、文字及节点不被裁切，不造成布局位移。
8. 现有路线顺序、票面、日期切换和首页相关测试全部继续通过。
