# Agent 研究进度与首批候选

## 目标

让双人讨论时能看到 Codex 正在做什么，并在发现候选后尽快获得可讨论的预览；共同决定只接收已核验候选。

## 体验

- 页面展示四步进度：范围确认、搜集候选、核验来源、写入共同决定。
- 目标在启动后 1–3 分钟显示首批候选；每项候选卡显示名称、位置和“待核验”状态。
- 核验通过后候选升级为可讨论项；失败时从预览中移除，并显示简短失败说明。
- 3 分钟未发现候选时显示仍在研究、可继续等待或停止的提示；达到研究上限时明确失败并撤销授权。

## 安全与数据边界

- Bridge 只向页面传递阶段、计数和安全候选摘要，不传递提示词、凭据、配对材料或内部日志。
- 未核验候选只保留在本机研究状态，绝不写入共同决定或服务端候选集合。
- 服务端继续在提交时复核证据，保留现有签名 scope、顺序号和授权检查。

## 实现边界

- 将研究输出处理改为：发现候选即更新本机状态；验证完成后才提交批次。
- 扩展 `ResearchStatus` 与 Bridge 安全投影，支持当前阶段、候选计数、待核验候选摘要与等待提示。
- `DecisionAgentPanel` 渲染进度、预览卡和超时操作。
- AgentRun 有效期与研究上限保持一致；不单纯延长授权来掩盖无进度运行。

## 验收

- 启动后页面立即显示当前阶段。
- 候选发现时可在不写入服务端的情况下展示为待核验。
- 核验失败不产生共同决定候选。
- 3 分钟无候选和研究超时均有可见、可操作的状态。
- 现有 Agent 签名、scope 和提交验证测试继续通过，并新增上述状态转换测试。
