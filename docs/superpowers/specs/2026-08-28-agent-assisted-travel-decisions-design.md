# 双人旅行 Agent 决策层设计

## 目标与范围

在既有共享旅行应用之上增加一层本地 Desktop Agent 辅助能力。它帮助两位旅行者形成公开偏好、检索并核验酒店/餐厅/景点候选、提出可解释方案，并将共同决定沉淀为可在手机端使用的行程。

第一阶段覆盖酒店、餐厅与景点，不包含下单、支付、抢票、餐厅订位或高铁查询。

## 已确认的体验

### 共同偏好

- 两人各自完成一份约五分钟的问卷。
- 问卷以快速点选为主：预算范围、住宿标准、出行节奏、步行/排队容忍度、餐饮偏好、景点类型与避开项。
- 每题可选填一句原因；“一定要有”“坚决不要”和其他补充使用自由输入。
- 两人的作答、原因、修改人和修改时间立即对彼此公开。
- 两人均完成或主动跳过后，Agent 才生成共同偏好、分歧及可执行取舍；它不隐藏权重，也不替任何一方作决定。
- 后续修改问卷会重新生成摘要，不会覆盖既有暂定或最终行程。

### 提案与共同决定

- Agent 每次提出 2–4 个候选，而不是直接倾倒搜索结果。
- 候选卡展示与此次决定有关的证据：房型或菜品/景点条件、含税价或票价、位置、距离、取消/营业信息、来源与查询时间。
- 两人可分别点赞、反对或留下理由。Agent 使用明确的共同偏好与分歧再次筛选。
- 任一人可把候选加入“暂定行程”。最终确认是两人出发前的显式动作；确认后仍可回退为暂定。

### 视觉语言

- 所有新增页面沿用已有“旅行通行证”视觉系统：米白纸张、深绿印刷、橙红日期/核验章、路线叙事与票根。
- 不使用通用后台卡片或 SaaS 流程图风格。
- Agent 能力以来源证据、核验章和提案票根呈现，重点是“为什么适合你们”，而不是“AI 正在运行”。

## 数据与 Agent 边界

### 数据来源

- FlyAI 用于酒店、餐厅/景点等的快速候选召回与当次价格快照。
- 高德用于 POI 实体、地理编码、路线与天气等地图事实。
- Chrome 中已登录的飞猪、携程、Trip.com 或酒店官网用于重要候选的最终复核。
- 网页详情页是同一日期、人数、房型、税费和取消条款下的优先证据；FlyAI 与网页价格不一致时不做平均，显示差异并以网页复核为准。

### 本地 Agent

- Agent 仅在用户 Desktop 开着时运行；手机旅行期间不依赖它在线。
- Agent 读取共享行程与公开偏好，调用 FlyAI、高德与当前已登录 Chrome，并将提案和核验结果写回共享数据库。
- 允许使用当前浏览器的已登录会话完成查询；不读取、持久化或下发 Cookie，不下单、不付款、不点击产生交易的确认动作。
- 网站前端不持有 FlyAI、高德 Web Service Key、浏览器登录态或 Codex 凭据。

### 手机端

- PWA 在 Agent 离线时读取已保存的暂定/最终行程、地点与最后核验快照。
- 价格、库存、票务与营业信息必须显示最后核验时间，不能表示为持续有效的承诺。

## 候选与证据模型

每个候选至少包含：

- 稳定实体标识、类别（酒店/餐厅/景点）、名称与坐标；
- 旅行适用日期、人数和关键约束；
- 结构化快照（价格、房型/菜品/票种、库存或营业信息、取消条件）；
- 来源系统、来源 URL、查询时间、过期时间或复核状态；
- Agent 推荐理由、两人的表态与理由；
- 行程状态：`candidate`、`web_verified`、`tentative`、`confirmed`、`needs_takeover`、`stale`。

`web_verified` 只能由浏览器复核任务在关键字段齐全后写入；`confirmed` 是用户动作，永远不由 Agent 自动写入。

## 异常处理

- 网页需要登录、验证码、风险控制、加载失败或字段缺失时：写入 `needs_takeover`，保留候选和失败原因，不标记网页核验成功。
- 证据过期、价格发生变化、房型/库存消失时：降级为 `stale` 或 `candidate`，保留历史快照与差异。
- FlyAI 的筛选或语义与事实冲突时（例如“近尖沙咀”却返回远区，或“直达”实际经停）：用坐标/结构字段二次判定；不直接相信展示标签。
- 无法判断真实性时，Agent 明确说明不确定，不补造答案。

## 验收与测试

1. 两人的问卷答案、原因与修改记录可实时同步且彼此可见。
2. 两人完成后生成明确的共同偏好和分歧摘要；重新填写会重算摘要。
3. 每轮提案限制在 2–4 个，且包含推荐理由和来源快照。
4. 网页复核仅在房型/适用日期/价格/关键条款满足条件时赋予 `web_verified`。
5. 被登录、验证码或风控阻断的任务必须进入 `needs_takeover`，不产生虚假核验。
6. 暂定、最终确认和回退的操作对两人实时可见，Agent 不自动确认。
7. Desktop Agent 关闭后，手机端仍能读取保存行程与最后核验时间。
8. 浏览器凭据和服务端密钥不会进入前端打包产物或共享数据。

## 非目标

- 任何交易执行：预订、支付、改签、抢票、订位。
- 高铁查询与 12306 非官方抓取。
- 将任何聚合价格当成最终成交价格。
- 在用户 Desktop 关闭后仍声称数据可实时刷新。
