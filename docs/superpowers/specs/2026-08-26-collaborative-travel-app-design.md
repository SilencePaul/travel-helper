# 双人协作旅行规划 App 设计规格

- 状态：已完成对话设计确认，待用户审阅本文
- 日期：2026-08-26
- 当前行程种子：北京 → 深圳 → 香港 → 澳门 → 珠海 → 北京
- 现有入口：飞书文档《2026 十一北京—深港澳珠双人游｜预算与行程》

## 1. 背景与目标

现有飞书文档保存了第一版粗略计划，但酒店比较、真实交通路线、地点详情、协作编辑和信息更新能力不足。新产品是仅供一鸣和美垚使用的双人旅行控制台：既能在地图上理解每天怎么走，也能共同选择酒店、维护订单与预算，并让 Codex 持续补充公开信息。

文案中的“浅浅的计划”只表示“昨天先浅浅计划了一下”，不是同行人的名字。产品中的同行人统一显示为“一鸣 / 美垚”。

成功结果：

1. 旅行总览、每天路线、酒店、餐厅、景点、订单与预算可以在线编辑并实时同步。
2. 每一段步行或公共交通显示真实沿路线路、距离和预计时间，而不是坐标直线。
3. 酒店能够按含税价格、地理位置和整趟通勤成本比较。
4. 餐厅和景点具有图文详情、价格、推荐内容与可追溯来源。
5. 行程天数可随日期和人工编辑动态变化，不限于当前 D1–D6。
6. 飞书文档保留为易读摘要和应用入口，完整交互由内嵌 App 提供。

## 2. 范围与明确不做的内容

首版包括：

- 飞书双账号登录与仅限两人的访问控制
- 旅行总览、动态日期、每日时间线与高德地图
- 酒店比较器、地点详情抽屉、订单和预算
- 勾选、备注、排序、修改历史和实时同步
- 天气、价格、营业时间及社区攻略的 Codex 建议收件箱
- PWA、最近行程离线查看和断网编辑队列
- 腾讯云 CloudBase 部署及飞书文档内嵌

首版不包括：

- 网页内的持续定位、锁屏运行、偏航重算和语音导航
- 在应用内直接完成酒店、机票、门票或餐厅付款
- 面向公众的行程社区或不限人数的协作空间
- AI 未经确认直接改写正式行程
- 部署后的网页直接消耗 ChatGPT/Codex 订阅额度

## 3. 信息架构

### 3.1 总览

总览是整趟旅行的控制台，而不是纯文字列表：

- 顶部：旅行名称、日期、同行人、总预算、预订完成度和同步状态。
- 中部：动态生成的每日行程带。每一天显示城市、酒店、核心活动、预计步数、强度、温度和降雨概率。
- 底部：待处理事项、订单、天气或闭馆预警，以及 Codex 新发现。
- 进入可靠天气预报窗口后，高降雨概率日期使用清晰但不惊扰的强调色，并展示可采纳的雨天替代路线；尚未进入预报窗口时显示“待预报”，不展示虚假的精确概率。
- 点击任意日期进入该日的“时间线 + 大地图”。

### 3.2 每日路线

桌面端使用左侧时间线、右侧大地图；移动端使用上方地图、下方时间线。地点卡、地图标记和详情抽屉保持双向联动：

- 点击地点卡：地图聚焦对应标记并打开地点摘要。
- 点击地图标记：时间线滚动并高亮对应地点。
- 地点之间显示交通方式、真实沿路线路、距离、时间和换乘摘要。
- 切换日期时同时更新标题、天气、时间线、地图视野、路线、酒店起终点和当天预算。

### 3.3 酒店比较器

酒店比较器使用候选卡片与地图联动，字段包括：

- 含税总价、每晚价格、房型和面积
- 早餐、取消政策、评分和价格更新时间
- 距地铁或主要交通节点的步行距离
- 到每天第一个、最后一个地点以及机场/车站的实际交通时间
- 街区特点、明显优点和明确缺点
- “位置最好”“性价比最高”“最省体力”等可解释结论

选中酒店后，系统重新计算入住晚数、住宿预算、每天起终点、交通时间和预计步数。比较数据保留平台链接及抓取时间，不把过期房价展示成当前价格。

### 3.4 订单与预算

- 机票、酒店、交通、门票和餐饮分别记录预计、已付和待付金额。
- 勾选已预订或已付款后，两人实时看到变化。
- 日期或酒店变更影响已有订单时，先显示冲突列表，不自动改订单。
- 预算按旅行总计、日期和类别切换查看。

## 4. 动态日期设计

日期不是固定的六个页面。旅行保存开始日期、结束日期和一个有稳定 ID 的有序日期列表；`D1、D2……`、日期与星期均为派生展示值。

支持：

- 修改开始或结束日期，自动增加或减少日期
- 手动新增、删除、复制和拖拽某一天
- 日期变化后自动重新编号
- 总览、地图标签、酒店晚数、预算和天气同步重算
- 长行程在桌面端横向滚动，在手机端使用可滚动日期条与日期选择器

删除有内容的日期时不直接删除地点和备注，而是把内容放入“待安排内容”。用户可将其移到其他日期或确认删除。日期变化导致机票、酒店或预约冲突时，必须明确列出受影响项目。

## 5. 地图与导航

### 5.1 地图服务

正式版使用高德地图 JS API 2.0。当前 Leaflet + OpenStreetMap 仅用于视觉原型，不进入正式实现。

地图能力包括：

- 自定义地点标记、酒店标记、聚合和信息窗体
- 步行、公交和驾车路线规划
- 沿道路或公共交通网络绘制线路
- 路段距离、预计时间、换乘和步行摘要
- 当前地图视野内地点筛选
- 独立天气服务提供的降雨概率和风险提示叠加层

正式接入前检查现有高德账号的以下权限：JS API Key 与安全密钥、Web 服务 Key、步行/公交/驾车路线、POI、港澳境外路线、域名白名单、日配额和 QPS。测试和日志不得输出完整密钥。

### 5.2 开始导航

网页内提供路线预览和文字分步指引，但不承担持续语音导航。点击“开始导航”时：

1. 直接唤起高德 App。
2. 传入目的地名称、经纬度和当前选择的出行方式。
3. 未安装高德时回退到高德网页路线页。
4. 若唤起失败，提供复制地址和坐标的明确操作。

这里不再出现地图提供商选择面板。

### 5.3 天气

降雨概率使用和风天气的坐标级每日预报，不依赖高德基础天气字段。界面必须区分预报与参考信息：

- 距行程超过 10 天：显示“尚未进入可靠预报窗口”，不伪造降雨概率。
- 距行程 10 天以内：显示每天白天和夜间的降雨概率、温度与更新时间。
- 距行程 48 小时以内：补充小时级趋势和官方灾害预警。
- 天气请求经云函数代理并缓存；总览和每日路线使用同一份带时间戳的数据。

## 6. 地点详情与内容来源

### 6.1 智能详情抽屉

电脑端从右侧覆盖地图约 40%；手机端从底部上拉，并可继续展开为全屏。关闭后仍保持原来的地图缩放、选中日期和时间线位置。

餐厅详情包括：

- 实景图和环境图
- 推荐理由、人均参考价、营业时间、排队和预约方式
- 招牌菜、单品参考价格和适合两人的点单组合及总价
- 顺路备选餐厅
- 攻略来源、更新时间、小红书和导航操作

景点详情包括：

- 实景图、门票、开放时间和预约入口
- 建议停留时长、最佳到达时段和拥挤程度
- 推荐游览顺序、拍照机位、天气影响和雨天替代项
- 官方来源、社区攻略、更新时间和导航操作

### 6.2 来源与可信度

- 营业时间、门票、预约和地址等事实优先使用官网、官方公众号或官方预订页。
- 排队、菜单、体验、拍照位置和避雷信息综合小红书、大众点评、携程、马蜂窝和哔哩哔哩等公开社区内容。
- 每条关键结论保留来源链接、采集时间和适用日期；来源冲突时展示差异，不静默选择其一。
- “小红书”先打开该地点的精选攻略列表，列表中可进入具体笔记，也可发起“地点名 + 推荐菜单 / 避雷 / 拍照机位”等搜索。
- 图片优先使用官方允许展示的素材、开放版权图片和两位用户上传的照片；正式应用不依赖不稳定的第三方盗链。

## 7. 协作、权限与变更历史

- 一鸣和美垚分别使用飞书 OAuth 登录。
- 访问控制采用明确的飞书账号白名单；默认不允许其他账号进入行程。
- 勾选、备注、排序、地点替换、酒店选择和预算修改通过 CloudBase 实时订阅同步。
- 写入采用乐观更新；成功后确认，失败时恢复原状态并说明原因。
- 使用稳定实体 ID 和版本号。两人修改不同字段时自动合并；修改同一字段时保留双方版本并让用户选择。
- 每次正式变更记录操作者、时间、旧值、新值和来源，支持撤销。
- 删除采用可恢复的软删除，避免误操作直接丢失行程。

## 8. Codex 信息更新

部署后的 App 不直接调用 OpenAI API，也不直接消耗 Codex 订阅额度。Codex 通过用户发起或计划任务执行公开信息检查，再将结果写入 CloudBase 的“新发现”收件箱。

检查范围：

- 天气和显著降雨风险
- 酒店价格、取消政策和房态变化
- 景点营业时间、闭馆和预约规则
- 交通调整和路线时长变化
- 新的社区攻略、菜单价格与避雷信息

每条建议包含来源、观察时间、影响范围、变更前后差异和建议动作。建议必须由一鸣或美垚点击“采纳”后才进入正式行程；“忽略”保留审计记录。酒店涨价、闭馆和暴雨等重大变化同时显示在总览和对应日期。

## 9. 技术架构

### 9.1 前端

- React + TypeScript + Vite
- 响应式 PWA，支持电脑和手机浏览器以及添加到桌面
- IndexedDB 保存最近一次可用行程快照与待同步编辑队列
- 高德 JS API 负责地图渲染；高德路线、和风天气及其他需要保护密钥的请求通过云函数代理

### 9.2 腾讯云 CloudBase

- 静态托管：发布前端资源和 PWA 文件
- 文档数据库：旅行、日期、地点、酒店、订单、预算、建议和操作日志
- 实时推送：两位用户的编辑同步
- 云函数：飞书 OAuth、权限校验、高德服务代理、和风天气代理与缓存、建议采纳事务
- 云存储：酒店、餐厅、景点和用户照片

所有服务端密钥只保存在腾讯云环境变量。前端只能使用受域名和配额限制的浏览器端地图凭据。

### 9.3 飞书

- 现有飞书文档继续呈现精简总览、关键酒店结论和操作入口。
- 完整 App 通过飞书支持的网页/HTML 嵌入块展示。
- 若客户端暂时无法加载嵌入块，同一位置显示可直接打开 App 的链接卡片。
- 重要人工决定可同步回文档摘要，但高频实时状态以 App 数据库为准，避免双主数据源。

## 10. 关键数据流

### 10.1 登录与协作

飞书 OAuth → 云函数交换身份 → 白名单校验 → 创建短期会话 → 加载旅行快照 → 订阅实时变更。编辑先在本地显示，再带实体版本和幂等 ID 写入 CloudBase；其他设备收到变更后合并到当前状态。

### 10.2 地图与路线

日期地点列表 → 云函数请求高德路线 → 缓存标准化路线结果 → 前端绘制真实路径并显示距离/时间。地点顺序、酒店或交通方式变化时只重新计算受影响路段。

### 10.3 AI 建议

Codex 任务收集公开信息 → 写入带来源的建议 → App 实时显示新发现 → 用户采纳或忽略 → 云函数以事务更新正式行程并写入操作日志。

## 11. 降级与错误处理

- 地图服务异常：保留最近缓存路线，展示文字地址、交通摘要和高德导航按钮，并标注路线更新时间。
- 天气或价格过期：显示最后更新时间和“需要刷新”，不把缓存值伪装成实时值。
- 离线：可查看最近快照；编辑进入队列。恢复网络后按顺序重放，冲突进入人工选择。
- 实时连接中断：显示清晰的“离线/正在重连”，不显示虚假的已同步状态。
- 高德唤起失败：回退网页路线，再提供复制地址。
- 来源页面失效：保留已记录的摘要、来源名称和采集时间，标注原链接不可用。
- 删除或日期缩短：内容先进入待安排区，必须再次确认才能永久删除。

## 12. 验收标准

1. 使用 4 天、当前 6 天和 8 天三组数据验证日期标签、总览、酒店晚数、预算和天气均能重算。
2. 北京、深圳、香港、澳门和珠海各至少验证一条步行路线与一条公共交通路线；地图线路必须沿路网绘制。
3. 点击时间线、地图标记和详情抽屉时，三处选中状态保持一致。
4. 餐厅和景点抽屉在桌面与手机上都能查看图片、价格、来源和导航。
5. 点击“开始导航”能带入正确目的地并唤起高德；失败路径可用。
6. 两个独立飞书账号和两个浏览器会话验证勾选、备注、排序、酒店选择和预算实时同步。
7. 同字段并发修改可看到冲突处理，不发生静默覆盖。
8. 断网后仍能打开最近行程，恢复网络后编辑可同步。
9. Codex 建议在未采纳前不改变正式行程，采纳后产生可撤销日志。
10. 非白名单飞书账号无法访问旅行数据。
11. 浏览器控制台无相关错误，桌面和至少一个手机视口无关键内容遮挡、溢出或滚动陷阱。
12. 飞书文档内嵌可加载完整 App；无法加载时入口卡片可正常跳转。
13. 行程超过天气可靠窗口时显示“待预报”；进入 10 天窗口后才显示带更新时间的真实降雨概率。

## 13. 当前设计决策摘要

- 视觉方向：地图为主、时间线为辅，整体克制、清晰，参考 TREK 的地图联动而不直接复制或 fork。
- 地图：正式版使用高德；原型中的 OpenStreetMap 不保留。
- 导航：直接唤起高德，不做网页内语音导航，也不显示提供商选择面板。
- 详情：桌面侧边抽屉、手机底部抽屉，可扩展到全屏。
- 总览：进入 10 天预报窗口后显示每日降雨概率；此前显示“待预报”，同时展示行程强度、酒店、预算和风险提示。
- 酒店：价格与位置通过整趟真实通勤成本联动比较。
- 协作：两人飞书登录、实时同步、可恢复历史。
- AI：Codex 只写入建议，人工采纳后才改变正式行程。
- 日期：完全动态，不固定 D1–D6。
