# 共同决定访问保护页设计

## 目标

把 `/decisions` 在缺少已登录成员或共同决定仓库时出现的裸文本保护页，改成与登录页和旅行通行证首页一致的正式状态页。权限条件和路由行为保持不变。

## 已确认方向

- 沿用项目的米白纸张、深绿正文、橙红印章、宋体标题和票根缺口，不引入新的视觉体系。
- 页面明确说明这是“共同决定”的访问条件，而不是功能故障：需要两位成员登录同一个共享行程。
- 保留单一可执行操作“返回行程”。当前路由没有登录回调，因此不展示无法工作的登录按钮。
- 用双人座位、`PRIVATE JOURNEY`、路线短线和 `ACCESS REQUIRED` 印章解释两人协作语义。
- 使用独立的 `DecisionAccessGuard` 展示组件，避免继续把正式页面塞在路由三元表达式中。

## 响应式与无障碍

- 桌面为说明区与票根双栏；窄屏改为单栏，票根不超出视口。
- 页面有唯一一级标题；条件说明保留 `role="status"`；返回操作使用原生按钮并提供清晰焦点态。
- 装饰图形不进入无障碍树；减少动态效果偏好下不播放入场动画。

## 验收标准

1. 未登录或缺少共同决定仓库时，仍不能进入私人共同决定数据区。
2. 页面能解释功能用途与进入条件，并可返回行程首页。
3. 桌面和手机首屏与现有旅行通行证视觉一致，无裁切、溢出或控制台错误。
4. 已登录且仓库可用的真实共同决定工作区不受影响。
