# 双人旅行 Agent 决策层：实现与证据附录

本附录承接 `prd.md`，供后续架构和实现工作使用，不改变其中的产品范围。

## 当前产品基础

- 现有应用已具备飞书登录、成员审批、共享行程日程、地图/路线、酒店比较、预算/订单、CloudBase 实时同步和 PWA/本地离线能力。
- 现有地点和酒店内容是构建时的静态数据：酒店页面中的价格为历史参考快照，不是实时库存。
- 旅行通行证是已确认的视觉规格：米白纸张、深绿排印、橙红印章与路线叙事；当前首页尚未完全按此规格实装。

## 已验证的数据源结论

### FlyAI

- 正式 `FLYAI_API_KEY` 已在本地工作树验证可用。
- 酒店查询返回具体价格、坐标、图片和飞猪详情跳转；体验模式的掩码价格已不适用于正式 Key。
- 景点查询可返回太平山顶、缆车等实体、坐标、图片和票价快照。
- 航班查询返回具体航班、时间、价格与跳转；高铁查询目前可为空，不是 MVP 阻塞条件。
- 已观察到筛选语义不可靠：例如“近尖沙咀”可能返回远区，“直达”标签可与经停结构冲突。因此它仅用于候选召回，位置、房型、经停等必须用结构字段或网页二次判断。

### 高德

- 当前工作树配置了 JS 地图 Key、JS 安全码和 Web Service Key。
- 高德用于 POI、坐标、地理编码和路线等地理事实；Web Service Key 只能在本地 Agent 或服务端使用。
- 当前天气实现使用 Open-Meteo，预报窗口约 16 天；后续架构再决定是否保留或替换天气来源。

### 网页复核

- 飞猪、携程、Trip.com 与酒店官网的当前详情页是适用日期、人数、房型、税费和取消条款的优先证据。
- 浏览器可使用用户已经登录的会话查询；不得保存 Cookie、复制登录态到共享库或进行交易动作。
- 受验证码、登录、风险控制或页面加载影响时，记录 `needs_takeover`，由用户接管 Chrome。

## 推荐的组件边界

1. **共享行程应用**：问卷、提案卡、反馈、状态流转与 PWA 阅读。
2. **本地 Agent 桥接层**：在 Desktop 在线时读取范围内的共享数据、执行有界查询、写回提案与证据快照。
3. **来源适配器**：FlyAI、高德和浏览器网页复核；每个适配器都返回来源、查询时间、字段完整度与错误状态。
4. **证据与状态服务**：维护候选、网页核验、暂定、最终确认、需要接管和过期状态；禁止 Agent 自动最终确认。

现有旅行 Schema 只表达日程、酒店、订单等，无法完整容纳偏好、候选、证据快照、Agent 任务和状态流转；实现时必须做兼容式扩展。现有整份旅行记录采用乐观版本保存，因此两人编辑和 Agent 回写的冲突需要显式可见，不能静默覆盖。

## 数据最小字段

- 实体：稳定 ID、类别、名称、坐标。
- 查询上下文：旅行日期、人数、房型/票种或其他关键限制。
- 快照：价格、税费标识、库存/营业、取消政策、来源 URL、查询时间。
- 决策：推荐理由、双方反馈与理由、状态变化、操作者、时间。
- 质量：字段完整度、网页核验标记、过期时间/原因、差异记录。

## 安全与操作约束

- 服务密钥与 Codex 凭据不进入前端变量或共享数据库。
- 不接入社区封装但依赖不透明代理、硬编码凭据或未授权抓取的旅行 MCP。
- 不做订单、支付、改签、抢票、订位。
- 手机旅行期只展示保存内容及最后核验时间；不宣称持续实时。
